# План порта Most Wanted

Как устроен исходный проект: [README-nfsu2.md](README-nfsu2.md). Здесь только то, что меняется для
`speed.exe`.

## Что от игры зависит, а что нет

Лифтер (x86 → C) работает с любым 32-битным PE от MSVC. Зависели от U2 только граница `.text`,
`_ftol2`, имя exe и релокации из безымянной секции. Это теперь берётся из самого exe.

Рантайм зависит от игры сильно: он называет функции и глобальные переменные SPEED2.EXE по адресам.
`tools/u2refs.py --summary` показывает 981 разный адрес. Большая часть приходится на модули фич U2
(свободная езда по сети, дрифт, гараж, сплитскрин, фоторежим, кооп и т. д.). В сборке MW их нет,
список ядра лежит в `tools/mw_core.txt`. В ядре остаётся 373 адреса:

| Файл | Адресов | Что это |
|---|---|---|
| `overrides.c` | 156 | обёртки над функциями игры: фиксы U2, ускорения, загрузка |
| `d3dx_hle.c` | 141 | статически слинкованный D3DX9 (эффекты, шейдеры) |
| `tools/inline_hot.txt` | 110 | горячие функции для инлайна (только скорость, можно пустой) |
| `com.c` | 80 | Direct3D/DirectSound/DirectInput и данные, которые они трогают |
| `framerate.c` | 71 | фиксированный шаг мира, пейсер кадров |
| `dinput_pad.c` | 26 | геймпад как DirectInput |
| `widescreen.c` | 22 | вывод в родном разрешении |
| `oracle.c`, `intro.c`, `debug.c`, `movie.c`, остальное | 87 | отладка, заставки, ролики, мелочи |

## Этапы

**0. Инструменты (сделано).** `u2refs.py`, `sigport.py`, `applyport.py`, `mwprobe.py`,
`exelayout.py`, `mwport.sh`, сборка `GAME=mw`. Проверка: `tools/test_sigport.py`,
`tools/sigport_check.py` (см. README).

**1. Лифт и загрузка без экрана.** `mwprobe.py` → `mwport.sh --apply` → `web/gen.sh speed.exe` →
`GAME=mw web/build.sh`. Сначала запуск без GPU (`runtime/web/null_platform.c` даёт заглушки), цель:
дойти до `Direct3DCreate9` и `CreateDevice`. Что, скорее всего, вылезет:
- импорты, которых рантайм не знает: точный список пишет `mwprobe.py` в `out/mw-imports-missing.txt`;
- реестр: `win32_ext.c` открывает любой ключ и отвечает по имени значения (`Install Dir`,
  `Language`…). Надо посмотреть, какие значения читает MW, и добавить недостающие;
- карта памяти: если образ MW заканчивается выше `0x00A00000`, сдвинуть базу второго модуля
  (`module.c`) и кучу рантайма (`win32_ext.c H_BASE`). `mwprobe.py` об этом предупредит;
- обёртка защиты: в репаке exe уже без неё («таблэтка не требуется»), `mwprobe.py` это проверит.

**2. D3DX.** `d3dx_hle.c` перехватывает функции статического D3DX9 по адресам. Если в MW та же версия
D3DX, сигпорт найдёт их точным совпадением. Если новее, часть функций придётся сопоставить руками по
`out/applyport.txt`, а таблицу `DX_WRAP` сверить с кодом.

**3. Обёртки `overrides.c`.** Каждая обёртка чинит что-то конкретное в U2. Для MW по каждой надо
решить: нужна ли она вообще, нашёл ли сигпорт её функцию, совпадает ли раскладка структур, которые
она читает (смещения полей движок мог поменять). Обёртку, которая не перенеслась, выключить, а не
оставлять с адресом U2.

**4. Первый кадр.** WebGPU, меню, загрузка трассы, звук. Потом `framerate.c` (фиксированный шаг мира
на высоком FPS), `widescreen.c`, ролики (`movie.c`, `tools/movies_av1.py`), геймпад.

**5. Своё для MW.** Всё, что было фичами U2, для MW делается заново, если понадобится: сеть, тексты
на русском (`language.c`) и т. д.

## Правила

- В git не идёт ничего из игры: ни exe, ни `gen/` (C из кода игры), ни `out/`.
- Адрес, у которого сигпорт дал `fuzzy`/`near` с оценкой ниже 0.9, не подставляется автоматически.
  Такой адрес надо проверить руками по дизассемблеру.
